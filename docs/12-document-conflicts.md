# Document Conflicts & Ambiguities

| ID | Topic | Doc A (PRD / Stack / Arch) | Doc B (SRS) | UI does | Impact | Decision needed from |
|---|---|---|---|---|---|---|
| CONF-01 | AI Features & Correlation | PRD lists AI Explanation, Context, Correlation, and Dashboard as core requirements. | SRS Section 2.1 (In Scope) omits AI, correlation, context, and dashboard entirely. | UI includes AI remediation notes, finding correlation context, and a dashboard (`dashboard.tsx`, `findings.tsx`). | Backend must implement costly AI workflows not specified in SRS functional requirements. | Product / Engineering Lead |
| CONF-02 | Dependency Scanner | Stack specifies `Trivy` for dependency scanning. | Arch Guide Section 2 specifies `OSV` as a possible implementation. | UI `data.ts` explicitly displays `Trivy` as the scanner and CVEs. | Need to lock in the dependency scanning tool to finalize Celery worker implementation. | Security / Architect |
| CONF-03 | User Management & Roles | PRD mentions "authorized users". Arch Guide mentions Authentication / Access Control. | SRS Section 3 defines an "Administrator" role that manages users and system configuration. | UI has a placeholder role string but zero screens for user management or admin configuration. | We lack requirements/designs for the Admin experience and user provisioning. | UI Designer / Product |
| CONF-04 | Private Repo Access / Tokens | PRD SEC-5 says "Credentials and repository access tokens must be protected." | SRS Data Requirements (Sec 6) lists no field for storing GitHub tokens/keys. | UI implies "Connect GitHub" but lacks a real OAuth flow or PAT input form. | Backend cannot clone private repos without a defined credential storage and gathering flow. | Product / Security |
| CONF-05 | Scan Status Granularity | PRD PR-005: "communicate the state". | SRS FR-05 specifies exactly 4 states: queued, running, completed, or failed. | UI implements a rich 10-stage progress bar with granular string states (`data.ts` `scanStages`). | If backend only emits 4 states, the UI's 10-stage loader will break or feel fake. Need to bridge the gap. | Engineering / Product |
| CONF-06 | Finding Review Workflow | PRD PR-012: "allow users to review and filter findings." | SRS FR-07 specifies "view and review findings". | UI allows marking findings as "Reviewed", "Resolved", or "False positive" (`data.ts:3`). | Backend DB must support these specific state transitions which are undefined in SRS data requirements. | Product |
| CONF-07 | Sandbox Mechanism | PRD SEC-2: "isolated from core application". | SRS NFR-01: "analyzed in an isolated environment." Arch Guide suggests "containers, temporary storage". | N/A | Need to finalize exactly *how* Celery workers isolate the git clone and analysis (Docker-in-Docker, VMs, etc.). | Security / DevOps |
